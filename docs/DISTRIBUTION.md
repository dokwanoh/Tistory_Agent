# 배포 개인정보 경계

이 저장소는 재사용 코드·합성 테스트·일반화한 설계 문서만 배포합니다. 운영 글, 댓글, 조회수·수익, 블로그 주소·닉네임, 사용자 홈 경로, 광고 ID, 계정·브라우저 프로필, 개인 승인 기록, 세션·미디어·실행 로그, 원본 Git 이력은 가져오지 않습니다.

원본 운영 자료는 삭제하지 않았으며 별도 운영 저장소에 그대로 있습니다. 새 배포본을 정리하는 작업은 원본의 공개 노출이나 기존 외부 복제본을 제거하지 않습니다. GitHub 저장소 소유자 계정과 원격 커밋 작성자 정보는 파일 내용과 별도 노출면입니다. 과거 커밋에 개인정보가 있다면 이력 재작성과 필요시 호스팅 측 캐시 제거가 별도 필요합니다.

## 유지 절차

1. `git status --short`로 예정된 파일을 확인합니다. `.local/`, `.artifacts/`, `content/`, 브라우저 상태와 `.env`는 배포하지 않습니다.
2. `python -m tistory_growth_os.release_audit`로 Git 관리 파일과 미추적 배포 파일을 검사합니다. 추가 비공개 식별어는 `TISTORY_PRIVATE_TERMS` 환경변수로 쉼표 구분 전달하며 파일에 저장하지 않습니다. 검사 결과는 일치 값 대신 파일·규칙만 출력합니다.
3. 전체 테스트, 계약 검증, 오프라인 검토 데모를 실행합니다. 권리 보류 사례는 실제 운영 글 대신 합성 입력으로 검증합니다.
4. 스테이징 diff 및 모든 branch/tag의 커밋 내용과 작성자 메타데이터를 확인합니다. CI 검사는 내용 회귀 방지이며 완전한 개인정보 탐지 보증이 아닙니다.
5. 실제 API 키가 유출됐다면 파일 삭제만으로 복구되지 않습니다. 키 폐기·재발급은 별도로 수행합니다.

새 사용자의 인터뷰는 private local 설정에만 기록합니다. 예제 호스트·모델은 테스트 입력이며 기본 로그인 대상이나 사용 가능 모델의 보증이 아닙니다. 온보딩에는 기존 설정 덮어쓰기, STOP 해제, 실게시 및 일정 생성 권한이 없습니다.
